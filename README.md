# 청년층 제주 관광 현황 대시보드

### 👉 [대시보드 열기](https://gkang63-sys.github.io/jeju-youth-tourism-dashboard/)

청년층은 제주에서 어떤 여행을 하고 있을까? 20대 방문 추이, 지역별 방문, 인기 장소, 검색어, 블로그 후기를 한 화면에서 봅니다. 기간과 지역 필터를 바꾸면 지표와 차트가 함께 바뀝니다.

서버와 API 키 없이 동작하는 정적 페이지입니다. 모든 집계는 브라우저에서 합니다.

## 실행

웹에서 바로 보기: https://gkang63-sys.github.io/jeju-youth-tourism-dashboard/

내 컴퓨터에서 보기: `dashboard/index.html`을 브라우저로 엽니다. `index.html`, `data.js`, `reviews.js`가 같은 폴더에 있어야 합니다.

## 화면 조작

- 넓은 화면(1,280px 이상)에서는 왼쪽 메뉴로 구역을 오갑니다. 그보다 좁으면 필터 아래 알약 줄을 씁니다.
- 휴대폰에서는 「필터 열기」를 눌러 필터를 펼칩니다.
- 지도 위 「동 지역 확대」 버튼으로 제주시·서귀포시 시내 동을 크게 봅니다. 읍면동을 누르면 지역 필터가 바뀝니다.
- 인기 장소 표의 「교통·주거·생활 시설 빼고 보기」를 켜면 공항·주차장·마트·아파트 같은 카테고리 109종을 빼고 순위를 봅니다. 뺀 목록은 표 아래에 있습니다.

## 변경 기록

### 2026-11-04 색과 분석 결과 요약

- 구역마다 강조색을 하나씩 정했습니다(01 파랑, 02 주황, 03 초록, 04 보라, 05 분홍, 06 청록, 07 회색). 구역 번호, 제목 밑줄, 카드 윗선, 작은 라벨, 강조 숫자, 왼쪽 메뉴와 알약 줄의 점에 씁니다. 글자에 쓰는 강조색은 바탕 대비 4.5:1 이상입니다.
- 대표 지표 옆 카드 4개는 연한 색 바탕으로 바꿨습니다.
- 검색어 워드클라우드 글자를 주소 기준 시로 칠합니다(제주시 파랑, 서귀포시 주황, 확인 불가 회색). 지역 차트와 같은 색이며 범례를 달았습니다. 분류(관광지 등)로 칠하지 않은 것은 상위 60개 중 56개가 관광지라 색이 거의 하나가 되기 때문입니다. 색은 색약 검사(모든 쌍)를 통과했습니다.
- 「분석 결과」를 핵심 숫자 카드 4개와 한 줄 실행 제안 4개로 줄였습니다. 긴 문장(확인된 사실·해석·추가 확인 사항·실행 제안 전문)은 「자세히 보기」를 누르면 펼쳐집니다.
- 컴퓨터가 어두운 모드여도 화면은 늘 흰 바탕으로 보입니다(검정 바탕은 읽기 어렵다는 의견 반영). 왼쪽 메뉴도 검정에서 연한 회청색 바탕으로 바꿨습니다.
- 검증 스크립트는 접힌 분석 문장도 읽도록 고쳤습니다.

### 2026-11-04 검토 후 수정

- 자료를 다시 만들어도 문구가 맞도록, 코드에 직접 써 두었던 기간·행 수·숫자를 자료에서 계산합니다. 맨 위 「자료별 기간」, 빈 화면 안내의 자료 기간, 기간 끝 경고, 「자료 기준」 표의 기간과 행 수, 「추가 확인 사항」의 숫자(최대 행 수, 도착건수 불일치 행, 월별 행 수가 늘어난 달)가 해당합니다.
- 「해석」의 블로그 비율에 분모(불만 검색어로만 모은 글을 뺀 5,290건)를 밝혔습니다. 온라인 후기 칸의 전체 건수(6,306건)와 다른 이유도 적었습니다.
- 연도별 선그래프에 넷째 해 색(회색)을 더했습니다. 다섯째 해부터는 같은 색을 점선으로 다시 써서 2027년 이후 자료가 들어와도 선이 비지 않습니다.
- 지도를 동 지역으로 확대한 채 다른 시나 읍·면을 고르면 전체 지도로 돌아갑니다(전에는 확대가 남아 회색 지도만 보임). 「초기화」도 지도 확대와 말풍선을 되돌립니다.
- 기간 끝을 2026-08 뒤로 고를 때의 안내가 자료별 마지막 달을 정확히 씁니다(예: 2026-10만 고르면 인기 장소는 2026-09까지라고 밝힘). 값이 없는 달은 0으로 치지 않는다는 점도 적었습니다.
- 블로그 해석을 고쳤습니다. 블로그는 '20대'·'혼자 여행'을 넣은 검색어로도 모았으므로, 비율로 청년층 전체의 선호나 교류 수요를 추론하지 않고 조사 주제를 찾는 데만 씁니다. 실행 제안의 「혼자 여행 소재」 문구도 맞췄습니다.

### 2026-11-04 화면 수정

오류·모순 수정
- 「방문객 수」가 실제 인원이 아니라는 안내를 첫 지표 아래에 넣었습니다. 연령대 합은 입도 관광객의 3~4배, 읍면동 합은 10~13배입니다.
- 성별 필터를 바꾸면 월별 표의 「전년 동월 대비」도 같은 성별 기준으로 계산합니다(전에는 남녀 합계였음).
- 지역을 한 읍면동으로 고르면 「확인된 사실」이 그 읍면동의 순위를 씁니다(전에는 다른 읍면동을 상위로 나열함).
- 「관광객 도착」·「도민 도착」을 고르면 인기 장소 합계도 같은 기준으로 보여 줍니다.
- 지역·방문객 구분 필터가 적용되지 않는 지표(20대 방문, 블로그 후기)에는 미적용이라고 밝힙니다.
- 「해석」의 블로그 건수를 기본 기간(2024-01 ~ 2026-08)으로 맞췄습니다(95건 → 86건, 후기 칸과 같은 수).
- 기간 필터 끝 달 안내를 실제 값(2026-10)으로 고쳤습니다.
- 분석 문장 속 날짜·숫자를 코드에 고정하지 않고 자료에서 계산합니다.

디자인·배치
- 흰 바탕·검정 글자·고정폭 번호 라벨·검정 알약 버튼으로 바꿨습니다(피그마 홈페이지 스타일 참고). 대표 지표는 파란 카드에 월별 추이선을 넣었고, 증감은 화살표 배지로 보여 줍니다.
- 차트 색은 색약인 사람도 구분되는지 검사해, 밝은 화면·어두운 화면 모두 통과한 색입니다.
- 화면 폭 1,200px 미만에서 표가 많은 카드는 한 줄을 다 써서 오른쪽 열이 잘리지 않습니다.
- 워드클라우드가 상위 60개를 모두 배치합니다(전에는 23개가 빠짐).
- 온라인 후기 칸 위에 표본이 작다는 안내를 넣고, '20대' 언급 0건 항목은 접었습니다.
- 자료를 받는 동안 안내 문구와 빈 카드 표시를 보여 주고, 자료 파일을 미리 받기 시작합니다.

검증: `python dashboard/verify_dashboard.py` 대조 3,673건, 실패 0건.

## 배포 상태

2026-11-04에 저장소를 공개로 바꿨습니다. 저장소에 올라간 `dashboard/data.js`(관광 데이터)와 `dashboard/reviews.js`(블로그 후기 분류 결과)는 누구나 볼 수 있습니다.

2026-11-04부터 GitHub Pages로 공개합니다. 저장소 Settings → Pages의 Source는 「GitHub Actions」입니다. 배포 설정 파일 `.github/workflows/deploy-pages.yml`이 `dashboard` 폴더의 `index.html`, `data.js`, `reviews.js`만 웹사이트로 올립니다.

- 대시보드: https://gkang63-sys.github.io/jeju-youth-tourism-dashboard/ (예전 주소 `.../dashboard/`도 같은 화면)
- 이 세 파일이나 배포 설정 파일이 바뀌어 main에 올라오면 자동으로 배포되어 1~2분 뒤 반영됩니다. Actions 탭의 Deploy dashboard에서 Run workflow로 직접 실행할 수도 있습니다.

## 주의

- API 키를 파일에 직접 쓰거나 올리지 마세요. 키는 `dashboard/.env`에만 두고, 이 파일은 `.gitignore`로 제외되어 있습니다.
- 블로그 후기는 제목과 요약을 낱말 규칙으로 분류한 것입니다. 작성자 연령을 확인한 것이 아니며, 건수는 대략의 크기로만 봐야 합니다.
